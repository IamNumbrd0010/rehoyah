================================================================================
1. PROJECT OVERVIEW & WHAT REHOYAH'S WEBSITE IS INTENDED TO DO
================================================================================
This codebase is the complete frontend web application for REHOYAH, a Nigerian
interior and exterior finishing, paints, decor materials, custom furniture,
and renovation brand.

It brings together five connected experiences in one React application:
  1) Public Brand Website (Home, About, Services, Projects, Inspiration, Contact)
  2) Online Storefront Demo (Shop catalogue, Product Detail, Wishlist, Cart Drawer)
  3) Service Lead Flows (Request a Quote with review step, Book Consultation)
  4) Customer Portal (/account/*) for orders, saved items, quotes, projects, profile
  5) Staff Workspace (/staff/*) and Admin Control Center (/admin/*)

Every page reads and writes through clean JavaScript service modules inside
`src/services/`. Right now those services run on demo data and browser
localStorage so you can test every workflow before wiring your real backend
and database.

================================================================================
2. EXACT TECHNOLOGY CONSTRAINTS
================================================================================
- Built strictly with: React 19, Vite, JavaScript (.js), JSX (.jsx), and CSS.
- Routing: react-router-dom (BrowserRouter, Routes, Route).
- Icons: lucide-react.
- NO TypeScript (.ts, .tsx, or tsconfig.json) is used anywhere in the project.
- NO backend server, database connection, or secret API keys are wired yet.

3. HOW TO INSTALL DEPENDENCIES & START THE DEVELOPMENT SERVER
================================================================================
1. Make sure Node.js (v18+ or v20+) and npm are installed.
2. Open a terminal in the project root folder.
3. Install dependencies:
     npm install
4. Start the fast Vite development server on port 3000:
     npm run dev
5. Check JavaScript/JSX syntax:
     npm run lint
6. Build optimized production files into `dist/`:
     npm run build

15. BACKEND INTEGRATION SLOTS & REPLACING SERVICE MODULES
================================================================================
Every UI page calls `src/services/*.js` rather than writing raw `fetch` calls
inside JSX components. To connect your backend:
  1. Set `VITE_API_BASE_URL` in your `.env` file (never store secrets in Vite).
  2. Open each file in `src/services/` and replace the `readDemoStore` /
     `writeDemoStore` demo implementation at the marked `TODO` comments with
     `fetch()` / SDK calls to your backend API.
  3. Keep the returned object shapes consistent (`{ ok, data, error }`).
  4. Set `DEMO_MODE: false` in `src/config/appConfig.js`.
  5. Remove the Demo Role Switcher from `SiteHeader.jsx`, `DashboardTopbar.jsx`,
     and `LoginPage.jsx`.

See `src/services/README.md` for full function-to-table mappings.

18. HOW REAL AUTHENTICATION SHOULD BE CONNECTED
================================================================================
- Use an HTTP-only cookie session backend or managed auth (Supabase Auth /
  Firebase Auth / Express + bcrypt + JWT).
- Hash passwords server-side; NEVER compare or store passwords in browser JS.
- Public `/register` MUST hardcode `role = 'customer'` on the server and ignore
  any `role` field sent from the browser.
- Provision Staff and Admin accounts only through authenticated Admin invite
  endpoints with expiring one-time invite tokens.

================================================================================
19. HOW TO CONNECT A REAL DATABASE WITHOUT REWRITING UI COMPONENTS
================================================================================
Because components only call `productService.getProducts()`,
`quoteService.createQuoteRequest()`, `orderService.createOrderDraft()`, etc.,
you only need to update the inside of each file in `src/services/`. The React
pages and components do not need to be rewritten.

================================================================================
20. HOW SECURE IMAGE / FILE STORAGE SHOULD BE ADDED
================================================================================
1. Replace `uploadService.uploadImage()` so it requests a short-lived signed
   upload URL from your authenticated backend endpoint.
2. Upload the file directly from the browser to S3 / R2 / Supabase Storage /
   Firebase Storage, then save the resulting file key/URL in your database.
3. Validate file MIME type, size limit, and user authorization on the server.

================================================================================
21. HOW PAYSTACK PAYMENT INTEGRATION SHOULD BE ADDED SAFELY
================================================================================
1. Customer clicks Checkout -> Frontend sends cart item IDs + quantities to
   `POST /api/orders` on your backend.
2. Backend fetches authoritative prices from the database (never trust prices
   sent from the browser), creates an unpaid order, and calls Paystack's
   Initialize Transaction API using your **server-side secret key**.
3. Frontend redirects to Paystack or opens Paystack Inline using your
   **public key only**.
4. After payment, your backend verifies the transaction reference with Paystack
   AND handles Paystack signed webhooks before marking the order `Paid`.

24. TROUBLESHOOTING TIPS (VITE / NPM)
================================================================================
- "Port 3000 is already in use": Stop any existing dev server or run
  `npx vite --port 3001`.
- Changes in `demoData.js` not showing up in the browser: Clear site
  `localStorage` in Browser DevTools > Application > Local Storage, then refresh.
- Missing package errors: Delete `node_modules` and run `npm install`.

25. BEGINNER-FRIENDLY GLOSSARY
================================================================================
- Component: A reusable piece of UI (like `ProductCard.jsx` or `Button.jsx`).
- Route: A URL path (like `/shop` or `/admin/orders`) mapped to a page in `App.jsx`.
- State: Data currently held in memory while the user interacts with a screen.
- Service Module: A file in `src/services/` that separates data fetching/saving
  from visual UI code.
- Database: Permanent server storage (like PostgreSQL) where real accounts,
  orders, and products live across all users and devices.
- Authentication: Verifying WHO a user is (e.g. signing in with email/password).
- Authorization: Checking WHAT an authenticated user is allowed to do (roles &
  permissions — must be enforced on the server!).
- API: The backend URL endpoints your React frontend talks to over HTTPS.
- Environment Variable: Configuration values stored outside source code (`.env`);
  only `VITE_*` variables are safe for browser code; secrets stay on the server.
- Demo Mode: The current safe preview mode where sample data runs locally in
  your browser without touching a live database or payment gateway.
